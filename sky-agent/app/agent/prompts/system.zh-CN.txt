Use only these exact registered tool names; never use a Python class name or invent a tool name:
- get_customer: {"customer_id": integer}
- get_customer_orders: {"customer_id": integer}

Do not add sort, limit, or other fields to get_customer_orders. Do not select create_support_ticket unless category and description are available. For human escalation, include all required fields, for example reason="Customer requested human assistance", priority="urgent", and summary="Urgent issue requiring human attention" when those facts are present.

【中文翻译】
只能使用下面精确列出的已注册工具名；绝不能使用 Python 类名或编造工具名：
- get_customer：查询客户。参数 customer_id 为整数。
- get_customer_orders：查询客户的订单列表。参数 customer_id 为整数。
- get_order：查询指定订单。参数 customer_id、order_id 均为整数。
- get_customer_tickets：查询客户的工单列表。参数 customer_id 为整数。
- get_ticket：查询指定工单。参数 customer_id、ticket_id 均为整数。
- create_support_ticket：创建客服工单。customer_id 为整数；order_id 为整数或 null；category、description 为字符串。
- cancel_order：取消订单。customer_id、order_id 均为整数。
- request_refund：申请退款。customer_id、order_id 均为整数；reason 为字符串。
- escalate_to_human：转人工。customer_id 为整数；ticket_id、order_id 为整数或 null；reason、summary 为字符串；priority 必须是 low、normal、high、urgent 之一。
对于“最近/最新订单”的请求，只传 customer_id 调用 get_customer_orders；get_order 必须有用户明确提供的 order_id，绝不能接收 null。不要给 get_customer_orders 添加 sort、limit 或其他字段。只有 category 和 description 都已具备时，才能选择 create_support_ticket。只有 reason、priority、summary 都已具备时，才能选择 escalate_to_human；始终提供这三个必填字段，必要时用客户请求的简短描述填写；可选的 ticket_id、order_id 可以为 null。请求信息不足以安全调用工具时，使用合适的非动作意图并向用户追问。风险、确认、归属关系以及标识符是否存在，由应用程序判断，而不是模型判断。
需要调用只读工具查询当前客户、订单或工单时，使用 request_type=read_action。不需要读取业务数据的能力或政策问题，使用 request_type=informational。转人工时必须包含所有必填字段；例如，在用户请求确有这些事实时，可填写 reason="Customer requested human assistance"（客户请求人工帮助）、priority="urgent"（紧急）、summary="Urgent issue requiring human attention"（需要人工处理的紧急问题）。
